1. The iOS Silent Switch Trap (AVAudioSession)

On iPhones, the physical ring/silent switch on the side of the device silences apps that use the default AVAudioSessionCategoryAmbient. Video applications (like YouTube, TikTok, or Instagram) configure AVAudioSessionCategoryPlayback with .moviePlayback to ensure video audio plays out loud regardless of silent mode: 

// ios/Runner/AppDelegate.swift
do {
  try AVAudioSession.sharedInstance().setCategory(
    .playback,
    mode: .moviePlayback,
    options: [.mixWithOthers]
  )
  try AVAudioSession.sharedInstance().setActive(true)
} catch {
  print("Failed to set AVAudioSession category: \(error)")
}

2. Slideshows vs. Videos: Eliminating the Play Button

A common UX anti-pattern occurs when multi-slide photo posts (carousels) are classified as video feeds, displaying a video play overlay on static images:

┌─────────────────────────────────┬─────────────────────────────────┐ │ VIDEO FEED (REEL) │ CAROUSEL FEED (SLIDES) │ ├─────────────────────────────────┼─────────────────────────────────┤ │ • Component: ReelVideoItem │ • Component: CarouselMediaItem │ │ • Controls: Play/Pause/Mute │ • Controls: Horizontal Swipe │ │ • Center: Play/Pause icon │ • Center: Zero Play Overlay! │ │ • Progress: Continuous ms timer │ • Progress: (Slide + 1) / Total │ └─────────────────────────────────┴─────────────────────────────────┘

ReelVault isolates carousels by inspecting URL paths (/p/ vs /reel/), checking media files, and allowing manual intake classification in ShareCollectionSheet.

3. Dual-Engine Media Playback Fallback

Because social platforms frequently update anti-scraping countermeasures and login walls:

  • Engine A (Local Sandbox): When a binary .mp4 is downloaded, it plays 100% offline via Flutter's VideoPlayerController.file with zero network dependency.
  • Engine B (In-Feed Live WebKit Stream): When direct download is blocked by anti-bot walls, ReelVault seamlessly renders the native WebKit embedded player with full video and audio directly in-feed.
