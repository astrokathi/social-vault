Native OS Share Sheet Interception & Resilient Media Extraction

Intercepting Android ACTION_SEND & iOS Share Extensions, Parsing OpenGraph, and Caching Ephemeral CDN Blobs.

1. The Native Bridge: How Share Sheets Work

When a user watches a reel on Instagram and taps Share → ReelVault, the operating system broadcasts an intent. Without proper configuration, mobile operating systems launch a second isolated process or drop the shared text.

In Android's AndroidManifest.xml, we configure two critical attributes: 

<activity
    android:name=".MainActivity"
    android:launchMode="singleTask">
    <!-- Intercepts plain-text URLs from social apps -->
    <intent-filter>
        <action android:name="android.intent.action.SEND" />
        <category android:name="android.intent.category.DEFAULT" />
        <data android:mimeType="text/plain" />
    </intent-filter>
</activity>

Why singleTask?

By default, Android uses standard launch mode, which spins up a brand-new Activity on top of the caller (Instagram). singleTask ensures that tapping ReelVault brings your already running app instance to the foreground and delivers the intent via onNewIntent.

2. URL Sanitization: Stripping Telemetry Parameters

Shared links from Instagram contain session trackers like ?igsh=MXJxbzF.... If two users share the same reel, different tracking query parameters would cause duplicate database entries:

Raw Shared String: https://www.instagram.com/reel/C9xLmP2oQ1z/?igsh=MWZ4Nm...&utm_source=qr │ ▼ UrlSanitizer.parseInstagramUrl() Clean Canonical Record: shortcode: "C9xLmP2oQ1z" canonicalUrl: "https://www.instagram.com/reel/C9xLmP2oQ1z/"

3. The Ephemeral CDN Trap: Why Storing URLs Fails

Social CDNs (like Facebook's fbcdn.net) sign URLs with cryptographic expiration tokens: 

https://scontent.cdninstagram.com/v/t51.2885-15/...?oh=00_AYB...&oe=66DE41F9

The oe= parameter is a hexadecimal UNIX timestamp. After 24 to 48 hours, any HTTP GET request to that link returns HTTP 403 Forbidden.

Our LocalAssetManager immediately streams the remote bytes into local application storage: 

await _dio.download(metadata.videoRemoteUrl, localFile.path);
// File is now saved permanently inside the local device sandbox!
