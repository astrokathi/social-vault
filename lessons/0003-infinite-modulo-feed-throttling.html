Modulo Arithmetic for Infinite Feeds & Watch Progress Throttling

Unbounded PageView.builder loops, High-FPS UI vs. 1Hz SQLite Telemetry Throttling.

1. The Problem with Standard PageViews

In standard Flutter applications, passing itemCount: items.length to a PageView.builder creates a bounded list. When a user with 5 saved videos reaches the 5th video, a scroll bounce occurs, halting the hypnotic loop.

To make an endless loop, we omit itemCount entirely (passing null) and map unbounded sequential integers into cyclic indices using the mathematical modulo operator (%): 

PageView.builder(
  scrollDirection: Axis.vertical,
  // itemCount is null -> Flutter treats the list as unbounded infinity!
  itemBuilder: (context, rawIndex) {
    if (items.isEmpty) return const EmptyFeedPlaceholder();
    
    // Cyclic resolution
    final activeItem = items[rawIndex % items.length];
    
    return ReelVideoItem(
      key: ValueKey('${activeItem.id}_$rawIndex'),
      item: activeItem,
    );
  },
)

2. High-Frequency UI vs. Low-Frequency SQLite Disk Writes

A video player's controller ticks 30 to 60 times every second. If an app performs an UPDATE vault_media_items SET watch_progress = ... on every tick, two catastrophic bugs occur:

  1. SQLite Lock Contention & UI Jank: Frequent flash storage writes starve Flutter's UI isolate.
  2. Reactive Stream Thrashing: Drift's reactive streams would re-broadcast 60 times a second, causing downstream widgets to rebuild continuously.

The Decoupled Dual-Clock Pattern

We update local widget state in memory at high frequency (smooth visual progress bar), while throttling persistent disk writes to at most once per 1,000 milliseconds: 

void _onVideoControllerTick() {
  final ratio = value.position.inMilliseconds / value.duration.inMilliseconds;
  final normalized = ratio >= 0.95 ? 1.0 : ratio.clamp(0.0, 1.0);

  // 1. Instant 60Hz UI repaint
  setState(() => _currentProgress = normalized);

  // 2. Throttled 1Hz SQLite commit
  final now = DateTime.now();
  if (normalized >= 1.0 || now.difference(_lastDbWrite).inMilliseconds >= 1000) {
    _lastDbWrite = now;
    ref.read(databaseProvider).updateWatchProgress(
      mediaId: widget.item.id,
      progress: normalized,
      positionMs: value.position.inMilliseconds,
    );
  }
}

3. Completion Threshold: The 95% Rule

Why consider a video 100% watched when it hits 95%? Credit sequences, ending watermarks, or user swipe gestures happen before the exact final frame. Setting completion at 95% ensures videos are reliably marked as finished even if the user swipes a split-second early.
